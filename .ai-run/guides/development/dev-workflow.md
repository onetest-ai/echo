# Dev Workflow

**Project**: Echo · **Stack**: Rust (+ vanilla JavaScript window UI, TypeScript status-line mod), tao + wry + tray-icon, clap, rquickjs · **Scope**: day-to-day build, run and debug: features, prerequisites, dev app beside Echo, UI review, runtimes, packaging

**Design**: `.ai-run/guides/design/claude-code.md`, `.ai-run/guides/design/window.md` — how it works and why; the rules here win.

## Build and package

### Rules
- R1. Build without the C-heavy parts when you don't need them: the default features are `transcribe` (whisper.cpp), `tray` (menu-bar icon, window, terminals), `brain` (bundled SQLite, Office/PDF readers) and `js` (QuickJS); `cargo build -p echoctl --no-default-features --features tray` keeps the app and window. Without `tray` there is no `echoctl window`; without `js` `echoctl plugin call` says "this build of Echo runs no plugin code"; `vulkan` adds whisper.cpp on the GPU (Windows/Linux, needs `VULKAN_SDK`). Evidence: `crates/echoctl/Cargo.toml::default`
- R2. Install what the scripts call before running them: `scripts/check-mod.sh` needs `claude` (plugin validate / test), `node` (the window's `*.test.mjs`) and `npx` (tsc; it skips tsc when no engine type declarations are found); the Windows cross-check needs the `x86_64-pc-windows-msvc` Rust target (`rustup target add x86_64-pc-windows-msvc`). Evidence: `scripts/check-mod.sh::npx`
- R3. Build for Windows with the MSVC Rust toolchain, Visual Studio Build Tools (C++; `package-windows.ps1` puts their CMake on PATH when `cmake` isn't found, plain `cargo` doesn't: in Git Bash add `/c/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin` to `PATH`, or whisper-rs-sys's build panics with "is `cmake` not installed?"), LLVM with `LIBCLANG_PATH` at its `bin` (bindgen; the release workflow installs it with choco when missing) and, for the release build (`--features vulkan`), the Vulkan SDK in `VULKAN_SDK`, without which the script stops. Evidence: `scripts/package-windows.ps1::VULKAN_SDK`
- R4. Package Windows with `scripts/package-windows.ps1 [-Phase all | stage | package]` → the MSI and zip in `dist`; it builds into a short target folder (`ECHO_BUILD_DIR`, default `<system drive>\echo-build`) because ggml's Vulkan shader build passes MAX_PATH under `target\release`, and stages in `ECHO_STAGE_DIR` (default `%TEMP%\echo-<version>`) so signing can run between `stage` and `package`. Evidence: `scripts/package-windows.ps1::ECHO_BUILD_DIR`
- R5. Give a dev build the runtime libraries it loads, not links: `scripts/fetch-pdfium.sh <dest>` (PDF pages for Recall) and `scripts/fetch-nemo-speech.sh <dest>` (Nemotron models) download pinned builds for Apple Silicon only, check their SHA-256 and copy the libraries with their licenses; then point `ECHOCTL_PDFIUM_DIR` / `ECHOCTL_NEMO_DIR` at `<dest>`, or fetch into `<config dir>/pdfium` / `<config dir>/nemo-speech`. Echo looks in the variable's folder, then the app's own copy, then the config dir. Evidence: `crates/echoctl/src/nemo.rs::candidates`

## Run and debug

### Rules
- R1. Run a dev app beside your installed Echo only with its own folders: `ECHOCTL_CONFIG_DIR=<dir>` and `ECHOCTL_HOME=<dir>`. The config dir holds `app.lock` (a second app on the same one exits with "Echo is already running"), `app-path` (each app start rewrites it, and the plugin's launcher follows it, so a dev app on the real config dir points the installed plugin at the dev binary), `ai.json` and plugins; `ECHOCTL_HOME` counts as a chosen data folder, so no first-run setup. Evidence: `crates/echoctl/src/app.rs::record_app_path`
- R2. Run your build with `target/debug/echoctl app run` (foreground, output in the terminal; `--no-tray` without the icon), never `echoctl app start` on a Mac with Echo installed: `app start` opens the installed `Echo.app` (`/Applications` or `~/Applications`) through LaunchServices when it finds one, and otherwise starts `app run --background`, whose output goes to `<home>/.echo/app.log` (Unix; started over past 5 MB). Stop either with `echoctl app quit`. Evidence: `crates/echoctl/src/app.rs::spawn_app`
- R3. Test capture permissions on a bundle: `LOCAL=1 scripts/package-macos.sh` builds an ad-hoc signed `dist/Echo.app` (no developer account, notarization or dmg; library validation off for the NeMo-Speech libraries), and macOS asks for Microphone, System Audio Recording, Accessibility and Screen Recording again after each build; clear a stale switch with `tccutil reset Accessibility ai.onetest.echo` (and `ScreenCapture`). The script refuses to rebuild while an Echo runs from `dist/Echo.app`. Evidence: `scripts/package-macos.sh::refuse_if_running`
- R4. Check permissions with the app running: `echoctl doctor` asks the running app (`app::app_health`) and otherwise reports the permissions of the terminal it was run from; `--probe` settles macOS System Audio Recording only while audio plays (a peak above zero = granted, silence = unknown), `--request` triggers the prompts, `--open microphone | system-audio | accessibility` opens the settings page, `--json` for scripts. Evidence: `crates/echoctl/src/permissions/mod.rs::doctor`
- R5. Set `ECHOCTL_DEBUG=1` to print what Echo otherwise keeps quiet, on stderr: the command, arguments and folder of a Claude session it starts (never the environment's values), macOS permission preflight and probe values, Whisper's top language-detection scores, the speaker model's turns, and what each speaking-marker candidate scored (`echoctl speaking <call>`). Evidence: `crates/echoctl/src/ai.rs::terminal_command`
- R6. Review window changes in a browser: `echoctl window --serve <port>` answers the page and its API live on 127.0.0.1 through the window's own `respond` (paging and search work; clicks reach the app only with `ECHOCTL_SERVE_IPC=1`, from that page's cookie and Origin, and the app's answer — the script the webview would run — runs in the page too; use it with a dev data folder), `echoctl window --export <dir>` writes the page, its assets, the first API answers and each minutes page as files for a static server, and `echoctl window --selftest` opens the real webview, checks `echo://` and IPC, and exits. All three need the `tray` feature. Evidence: `crates/echoctl/src/window/mod.rs::serve`
- R7. Try a change to `plugin/` in a Claude Code session started with `claude --plugin-dir plugin` after `scripts/build-plugin.sh` (the launcher prefers `plugin/bin`, which git ignores); package the app with `scripts/package-macos.sh` / `package-windows.ps1` only for permission or installer work. Evidence: `README.md::plugin-dir`
- R8. Look for what went wrong where Echo writes it: the app's own output in `<home>/.echo/app.log` (background launches), a minutes run's readable log in `<call>/claude.log` (window → Show log) beside its state in `<call>/notes-run.json`, and a call's transcription failure in `<call>/transcribe.error`. Evidence: `crates/echoctl/src/notes.rs::LOG`
