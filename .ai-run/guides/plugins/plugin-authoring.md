# Plugin Authoring

**Project**: Echo · **Stack**: Rust (+ vanilla JavaScript window UI, TypeScript status-line mod), tao + wry + tray-icon, clap, rquickjs · **Scope**: writing, testing, publishing and updating a third-party Echo plugin: manifest, host and client halves, marketplace

## Manifest

### Rules
- R1. Ship a plugin as one folder with `echo-plugin.json` at its root: `id` (1–40 chars, a–z 0–9 `-`, no leading `-`), `name` (≤ 60), `version` (`X.Y.Z[-pre]`), `echo` (`>=X.Y.Z`), optional `summary` (≤ 240), `uses`, `settings`, `main`, `client`, `widgets`, `skills`, `icon` (an `.svg` in the plugin folder, named with a–z 0–9 `.` `_` `-` `/` only, ≤ 16 KB, shown only as an image beside its work rows and ⌘K entries). Evidence: `plugins::valid_id`
- R2. Point `main` and `client` at a `.js`/`.mjs` inside the plugin folder; read any other file it ships with `ctx.package.read(path)` / `ctx.package.list(dir)`. Evidence: `jshost::package_file`
- R3. Declare each setting as `{key, label, type, default?, help?}`: `key` unique (a–z 0–9 `-` `_`), `type` `string` (default), `bool`, `folder` or `secret`; read it with `ctx.settings.get(key)`. Evidence: `plugins::set_setting`
- R4. Name in `uses` only capabilities Echo knows, in their shapes (`claude`, `schedule`, `deliver.to`, `deliver_provider.kinds`, `network.hosts` or `network.hosts_from` (string settings without a default), `channel.plugin`, `sessions`, `folders.what` (read-only, or `folders.write` to change them), `files.read` (other apps' files, each named in full), `sessions.commands` (its commands Claude in Echo may run), `sessions.scripts` (the scripts of its package skills Echo may run), `echo.read`/`write`, `signin.hosts` (1–4 plain host names, each once, no IP addresses: the hosts whose sign-in saved on this computer it gets), `signin.keep` (`true`: Echo keeps a sign-in it makes itself for those hosts, its own), `work` (`{}`: its items on My work and in threads' Work)); never `brain_source` or `export`. Evidence: `plugins::describe_folders`
- R5. Ask only for what the user can agree to line by line on the permission sheet; an update adding a line needs their agreement again (`echoctl plugin update --yes`). Evidence: `plugins::sheet`
- R6. Declare each Today widget in `widgets` as `{id, label, about?, kind, sizes?, heights?, height?, refresh?, params?}`: `id` unique (a–z 0–9 `-`), `label` 1–40, `about` ≤ 120, `kind` `stat`, `stats`, `chart`, `list`, `status`, `card` or `page` (a page needs a `client`), `sizes` of `S` `M` `L` each once (default `["M"]`), `heights` of `1` `2` each once, with `1` (default `[1]`: the rows of Today's grid it may take), `height` `hug` (default) or `fill`, `refresh` ≥ 60 s; at most 12, and only with a `main` to give their data; its settings in `params` as `{key, label, type, options?, default?}` — `type` `choice` (1–12 `options`), `bool`, `thread` or `client`, 6 at most. Evidence: `plugins::check_params`
- R7. Ship a skill Claude uses as it is (fixed instructions, references, scripts) as a package skill: a folder in the plugin (`skills/<name>/SKILL.md`, with `scripts/` and `references/` beside it as you need) named in `skills` (at most 10, with your runtime skills), `SKILL.md`'s frontmatter only `name` (the folder's name) and `description`, no `!` commands. Give skills whose text you build at run time with `ctx.sessions.skills` (Host half R11); one name is never both. Evidence: `grants::copy_package_skills`
- R8. Declare each script Echo may run as `uses.sessions.scripts: [{skill, script, readonly?, timeout?}]` (`script` relative to the skill folder, `readonly: true` only for one that changes nothing, which read-only routines may then run, `timeout` the seconds it may take, 300 by default, 3600 at most, the sheet naming one over 300); start it with a shebang (`#!/usr/bin/env node`; on Windows a `.ps1` runs with PowerShell, another script with the interpreter its shebang names) and name in `summary` or the skill what it needs on the computer: Echo ships no interpreter, and a missing one fails the run with its message. Evidence: `plugins::scripts::run`

## Host half

### Rules
- R1. Export `apply(ctx)` from the host half and register its commands, timers, event handlers and delivery ways inside it. Evidence: `jshost::load`
- R2. Write a command as `ctx.command(name, fn)`: `fn` takes JSON arguments, may be `async`, returns JSON and throws an `Error` to fail; keep a window-called command under 30 s. Evidence: `jshost::CALL_TIMEOUT`
- R3. Use `ctx.every(seconds, fn)` for periodic work (10 s minimum); never rely on timers in `echoctl plugin call` or `echoctl deliver`. Evidence: `jshost::no_timers`
- R4. Name each event in `uses.events.on` and subscribe with `ctx.on(event, fn)`; read a call's words with `ctx.echo.read('source', id)`, never from a payload. Events are not replayed — except `threads_changed` from another process (`echoctl project delete`, a terminal's `plugin call`), which waits for the running app (heard within about a second, or at its next start), at least once; a queued `renamed` or `deleted` of an id that by then belongs to a new thread is dropped. Evidence: `plugins::EVENTS`, `plugins::thread_values::take_queued`
- R5. Keep a plugin's own state with `ctx.store.read/write/list/remove/path`, by relative path only. Evidence: `plugins::data_dir`
- R6. Check `status` in the `{status, body}` that `ctx.http.fetch(url, {method, headers, body})` resolves; it rejects only when the host can't be reached. Evidence: `jshost::fetch`
- R7. Run Claude with `await ctx.claude.run({prompt, title, profile, model, tools, dir, timeout})` only with `claude` in `uses`; `tools: "skip"` needs `"claude": {"skip": true}`. Evidence: `claudejob::Tools::parse`, `plugins::may_run_claude`
- R8. Provide a delivery kind with `ctx.deliver.provide(kind, {label, send(msg)})` only for a kind in `uses.deliver_provider.kinds` (never `teams` or `mail`), and call `ctx.deliver.ready(kind, true)` once it can send. Evidence: `jshost::provider_ready`, `plugins::may_send`
- R9. Call `ctx.echo.read(kind, arg)` only for kinds in `uses.echo.read`, and `ctx.echo.dictionary.add(...)` only under `uses.echo.write: ["dictionary"]`. Evidence: `share::dictionary_add`
- R10. Get a folder with `await ctx.system.pickFolder(prompt)` (needs `uses.folders`) and read it as `(root, relative path)`, bulk reads through `ctx.fs.readMany/walk`; with `folders.write` change it with `ctx.fs.write/move/remove` (never through a link, never over another file); in a debug build answer the picker with `ECHOCTL_PICK_FOLDER=<dir>`. Evidence: `app::choose_folder`
- R11. Set `ctx.sessions.skills`, `ctx.sessions.read` and `ctx.view.hints` from `apply` on every load, each as the whole set (`[]` removes it). Evidence: `grants::drop_plugin`
- R12. Ask the user for a decision with `ctx.inbox.set(key, {title, why, urgent, go, actions: [{label, command, args, primary}]})` (key ≤ 80 chars), and `ctx.inbox.clear(key)` once it is settled. Evidence: `attention::inbox_items`
- R13. Bundle the host half into one file with no `import` of other files; the client half may import its own modules. Evidence: `window::plugins::plugin_file`
- R14. Keep large data in the store, not in JavaScript memory (64 MB shared by all host halves). Evidence: `jshost::set_memory_limit`
- R15. Give a widget's data with `ctx.widgets.provide(id, ({size}) => data)` — Echo asks it in the background, answered within 5 s, again after `refresh` — or push it with `ctx.widgets.set(id, data)` and take the widget off Today with `ctx.widgets.clear(id)`; only ids the manifest declares, 64 KB of data at most; work that needs Claude runs as a job whose result you `set`. Evidence: `jshost::widget_ask`
- R16. Shape a widget's data by its kind — `stat` `{value, unit?, label?, tone?, note?, progress?: {used, of}}`, `stats` `{items: [{label, value, tone?}]}`, `chart` `{type: bar|bars|line, points: [{label, value}], unit?, note?}` (values numbers), `list` `{items: [{title, sub?, link?}], empty?}`, `status` `{state: ok|warn|bad, title, text?}`, `card` `{title?, text?, link?}`; `tone` `good`, `warn` or `bad`; text is plain (Echo escapes it), a `link` only to `echo://`; check it with `echoctl widget show plugin:<id>:<widget>`. Evidence: `pluginWidgetHtml` (window script)
- R17. Give any widget `open` (an `echo://` place, or an `https://` page) and up to 3 `actions: [{label, command, args}]` — each runs your host half's `ctx.command(command)` with `args` on the user's click, then Today reads your widgets again; answer by `ctx.widgets.set` what changed. A plugin's `https://` link — a widget's `open`, a work row's `url` (R22), its ⌘K entry — opens only after the user confirms it (a second click within 30 s; one question on the page at a time). Evidence: `pluginWidgetHtml`, `linkAskStep` (window script)
- R18. Read a widget's settings from the `params` your provider gets (`ctx.widgets.provide(id, ({params}) => …)`: its defaults, then what the user set in Today's edit mode or with `echoctl today set`); Echo asks again when one changes, and never gives a value the setting doesn't take. Evidence: `today_layout::params_of`
- R19. Save audio or a picture with `ctx.http.fetch(url, {save: "<store path>"})` and show it from `/plugin/<id>/store/<path>`; put what you can lose under `cache/` (Echo removes it after 7 days) and remove the rest yourself with `ctx.store.remove`. Evidence: `jshost::sweep_store`
- R20. Name a skill's Echo CLI `${CLAUDE_PLUGIN_ROOT}/scripts/echoctl`, and list in `uses.sessions.commands` the commands of yours it runs (`plugin call <id> <command>`); in a terminal (`ctx.terminal`) only your plugin is loaded, so skip start-up work there. Evidence: `plugins::session_commands`
- R21. Keep what belongs to a thread (its repositories, its project) with `ctx.threads.set(thread, key, value)` — `key` 1–80 chars, `value` JSON of 16 KB at most, 64 keys a thread, 4 MB a plugin in all; `null` removes it; refused in a read-only routine and for a thread that doesn't exist — and read it with `ctx.threads.get(thread, key)` (null when none) and `ctx.threads.list(key)` (`[{thread, value}]`, threads gone left out); no grant, never your own thread keys in the store. A `threads.json` that isn't JSON makes `get` and `list` fail and is moved aside as `threads.json.bad-<time>` at the next change; a thread id used again inherits nothing. Hear a thread change with `threads_changed` in `uses.events.on` (from another process too, R4): `{thread, born, change: 'renamed', name, from}`, `{thread, born, change: 'merged', into, dropped}` (each key `into` lacks is moved to it; `dropped`: yours that didn't fit in its 64) or `{thread, born, change: 'deleted', values}` (your own values, removed: clean what you keep elsewhere); `born` tells this thread from a later one with its id. Evidence: `plugins::thread_values::changed`
- R22. Give the user's items tracked outside Echo (a review asked of them, an issue assigned) with `ctx.work.provide(({scope, thread}) => rows)` under `uses.work`: `scope` `"me"` (Today → My work) or `"thread"` (that thread's Work tab, `thread` its id); rows `[{id, title, kind, where?, url?, due?, late?, thread?}]` — `id` unique, `kind` short text (≤ 30), `url` https only (R17), `due` `YYYY-MM-DD`, `thread` on a "me" row also puts it in that thread's Work; 200 at most, text plain (Echo escapes it); one wrong row refuses the answer. My work shows a "me" row late, due by the week's end or undated (Echo's own undated tasks stay off): late first, then by date, the undated last; `late` is the row's flag or its `due` past, on the day drawn. Echo asks in the background (5 s) and draws the last answer, the page reading again until one comes; it asks again when the answer is a minute old or after `ctx.work.changed()`, a scope at most every 10 s (a `changed()` said sooner is asked once its time is up; one from inside `provide` is ignored). A provider that fails or is slow keeps its last good rows, marked "not updated", for 24 h after that answer, with a line in Settings → Plugins naming where. A thread's rows go when it is deleted or merged, a thread's scope not asked for in 30 days goes. Check it with `echoctl work show [--thread <id>]`. Rows are never in a ledger: Echo's Close and Claude stay off them. Evidence: `jshost::work::check_rows`, `today::plugin_row_shown`
- R23. Use the sign-in saved on this computer, never a token the user pastes: name the host in `uses.signin.hosts` (and its API host in `network.hosts`: the sign-in grants no network) and `await ctx.signin.get(host)` → `{token, from: "gh" | "git", user?}` (the GitHub CLI's token, else the password or token git's credential helper keeps — for a self-hosted git maybe the user's own password) or `null`. Echo asks for no password (the system keychain may ask once to allow it), runs each program from an empty folder without the caller's `GIT_*`, `GH_*`, `GCM_*` and `GITHUB_TOKEN`, gives each 10 s, keeps an answer a minute (none: 10 s) in memory only, and refuses it in a read-only routine. `ctx.signin.get(host, {fresh: true})` asks again and replaces the kept answer: after the token was refused (HTTP 401), not on every call. `ctx.signin.sources(host)` → `{gh, git}` (which programs are here, no sign-in read), so your section can say how to sign in (`gh auth login`). The sheet tells the user the plugin can act as them there and send it to the places it talks to: keep the token in memory and send it only to that host's API — never to the store, the window or a log. Without one there, sign the user in yourself — however the service does it (a device code, a browser sign-in), with your own client id and scopes, checked by you — and have Echo keep it: `uses.signin.keep: true`, then `ctx.signin.keep(host, token)` (one line, 8 KB at most) writes it to `<config dir>/signin/<plugin>/<host>.json` (0600) outside your store — your plugin's own: `ctx.signin.get(host)` hands it back first as `{token, from: "echo"}` to you only, no other plugin gets, replaces or forgets it, and it is deleted when your plugin is removed — and `ctx.signin.forget(host)` signs out; the same id from another marketplace, or a version that no longer says `keep`, starts without it; refused in a read-only routine. After a 401 on an `"echo"` sign-in, `{fresh: true}` gives the same one: offer to sign out and in again. Evidence: `plugins::signin::get`, `plugins::may_use_signin`, `plugins::signin::keep`
- R24. Test against made-up services, never the real ones: in a development build `ECHOCTL_TEST_HOSTS="<host>=http://127.0.0.1:<port>,…"` (or `http://localhost:<port>`, an optional path after it) sends `ctx.http.fetch("https://<host>/<path>")` for a host your manifest names in `network.hosts` to `<base>/<path>` (`save:` downloads too), never through a proxy; the grant is checked on the real host first, and an address the user listed (`network.hosts_from`) is reached as it is. It fails closed: while it is set, one wrong entry (malformed, or not a local address) fails every request, and a named host it doesn't map is refused ("isn't mapped in ECHOCTL_TEST_HOSTS"). Curl sends the fake `Host: 127.0.0.1:<port>`: serve hosts it must tell apart on different ports. A release build never reads it. Made-up `gh` / `git` first on `PATH` (`gh.cmd` / `git.cmd` on Windows) answer `ctx.signin.get` in any build (`tests/app_profile.md` → Plugins against fake services). Evidence: `jshost::test_hosts::test_host`
- R25. Run a script of yours from the host half with `await ctx.scripts.run(skill, script, args, {timeout})` → `{status, stdout, stderr}`: `args` a list of strings (no shell), `timeout` in seconds up to the script's declared one (its default), never more, stdout and stderr 1 MB each, a second run of the same script while one runs refused ("already running"); it runs in its copied skill folder with `ECHO_PLUGIN_SCRIPT=1` (nobody is there to answer a prompt: fail with a message instead of starting a sign-in) and `ECHO_PLUGIN_STORE` (your store folder). For data on a schedule (a fetch for a widget), run it from `ctx.every` and keep what it prints with `ctx.store` — no Claude run in between; a skill's script in a session hands its result to you with `plugin call <id> <command> '<json>'`. Evidence: `plugins::scripts::run`

### Constraints
| Do not | Do instead | Evidence |
|---|---|---|
| Write `settings.json`, `inbox.json`, `widgets.json`, `threads.json` or `work.json` with `ctx.store.write`, or remove `settings.json`, `threads.json`, `work.json` or the store folder itself with `ctx.store.remove` (Echo refuses those) | Use `ctx.settings.set`, `ctx.inbox.set` / `clear`, `ctx.widgets.set` / `clear` and `ctx.threads.set`; `work.json` is what `ctx.work.provide` answered, kept by Echo | `jshost::not_echos`, `jshost::inbox_file`, `jshost::widgets_file` |

## Client half

### Rules
- R1. Export `apply(ctx)` from the client half and add to the window only through `ctx` (`call`, `slots.add` on a known slot, `panels`, `activities`, `settings`, `palette`, `listen`, `ui`, `go`, `render`); put text on the clipboard only with `ctx.ui.copy(text)`, on the user's click or key (without the page's user activation, or where the engine can't tell, it throws — a guard against accidental copies, not a security boundary; tests log it as `copied: …`). Evidence: `loadPluginClients` (window script)
- R2. Escape every text you put in HTML with `ctx.ui.esc` and render Markdown with `ctx.markdown`. Evidence: `slotItems` (window script)
- R3. Draw a `page` widget with `ctx.widgets.draw(widget, ({data, size, theme}) => HTML)` from `data` only (its host half gives it by `provide` / `set`): the same data must give the same HTML, and the draw neither calls `ctx.render` nor keeps state in the page. Evidence: `pluginWidgetView` (window script)
- R4. Add a row to each thread's Profile with `ctx.slots.add('thread.profile', {id, label, render(thread) → HTML, after?(box, thread)})`: `thread` is `{id, name, client}`, drawn under the thread's Sources; `render` is synchronous (draw from what you have; a `ctx.render()` inside it is ignored), `after` runs once per box drawn afresh (fetch there, then `ctx.render()`), one row per id, and one that throws is left out, the Profile drawn without it. Evidence: `threadSlotRows`, `threadSlotAfter` (window script)
- R5. Act on your work rows with `ctx.slots.add('task.actions', {…, when: (t) => t.kind === 'plugin' && t.source === ctx.id, run(t)})`: `t.row` is the row, each row its own target; an item without `when` stays on Echo's tasks; after `run`, Echo reads the rows again. Evidence: `slotFor` (window script)

## Publishing

### Rules
- R1. Host a marketplace as a folder or git repository with `echo-marketplace.json` at its root (`{name, featured, plugins: [{id, source, categories}]}`), each entry's manifest `id` equal to its `id`. Evidence: `plugins::CatalogEntry`
- R2. Give users a marketplace source as `owner/repo[@ref]`, a git address (`https://`, `ssh://`, `git@`, `#ref`) or a local folder; a ref is a plain branch, tag or commit. Evidence: `plugins::parse_source`
- R3. Bump `version` for every change you publish. Evidence: `plugins::update_for`
- R4. Restart the app after `echoctl plugin install | update | enable | disable` from a terminal. Evidence: `plugins::page_op`
