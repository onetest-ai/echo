# Testing

**Project**: Echo · **Stack**: Rust (+ vanilla JavaScript window UI, TypeScript status-line mod), tao + wry + tray-icon, clap, rquickjs · **Scope**: Rust test isolation, fakes, node tests, functional tests (agent-run and person-run)

## Tests and checks

### Rules
- R0. Every change in behaviour starts from acceptance criteria and ends with them checked: each criterion has a functional test — a Rust test that proves the behaviour, a node test over an `app.js` block, or a check in the running window (`echoctl window --serve` on made-up data from `tests/fixtures/make-data.sh`, or a copy of a data folder, never the user's real one); test design is part of the implementation plan: its **Tests** part names the functional cases (R4) to add, change and remove, and the scenarios they go into — reconciling the area: each existing case of the area checked against the new behaviour, obsolete ones removed, duplicates merged, so no stale case stays — and they are written before the code and shown to the user with the plan; Rust and node tests come with the change, not on request; all of them run with the quality gates before it is called done. Evidence: `crates/echoctl/ui/workbench.test.mjs`
- R1. A test that touches the data folder or config dir takes `paths::testenv::folders(name)` first and keeps the guard alive; it is the only code that sets `ECHOCTL_HOME` / `ECHOCTL_CONFIG_DIR` (the variables are process-wide). Evidence: `crates/echoctl/src/paths.rs::testenv.folders`
- R2. Write Rust tests as a `#[cfg(test)] mod tests` at the end of the module they test, each named as the behaviour it proves in snake_case (`only_this_calls_files_and_the_previous_minutes`). Evidence: `crates/echoctl/src/guard.rs::only_this_calls_files_and_the_previous_minutes`
- R3. Wait for a lock just released with `testenv::eventually`, not a fixed sleep (on macOS a child process holds the descriptor until it execs). Evidence: `crates/echoctl/src/paths.rs::eventually`
- R4. Functional tests have two layers: **cases** in `tests/cases/<area>/TC-NNN_<slug>.md` (one behaviour each, the unit of coverage; the manual-qa format plus `run: agent | person` and `platform`) and **scenarios** in `tests/scenarios/S-NN_<slug>.md` (a user's journey chaining cases by path, in stages, each stage with its own result; agent runs execute scenarios, one runner each, the browser kept open between them, fresh data per scenario). A case may be a stage of scenarios or stand alone; runs execute the scenarios and the standalone cases. What Echo does is listed in the **functional map** `tests/feature-map/` (one JSON file per area with its features, one per entity with its state axes, so parallel work rarely touches the same file); a case names the features it checks in `requirements:`, and `tests/tools/feature-map.py check` (ids, axes, links, every agent case in a scenario) must pass, `render` draws the map with coverage as HTML. A change in behaviour adds, changes or removes its features in its area's file in the same PR — a mandatory step before the branch is pushed (git-workflow.md R1a; `feature-map.py changes main` prints the PR's `Map:` line and warns when app code changed without the map). Echo's rules for cases and scenarios are in `tests/app_profile.md`: made-up data built per run by `tests/fixtures/make-data.sh`, the window served from `target/debug/echoctl`, CLI steps with that data's env. `run: agent` cases are run inside scenarios by the manual-qa team (`tests/install.sh` installs it per machine; then the `test-run-lead` agent with the scenarios to run); `run: person` ones by a person. Cases are kept true like code: a change in behaviour updates its cases in the same PR, a removed feature removes its cases, a bug found by hand gets a case. Running them is a gate, not a courtesy: a change is not done, and its PR not opened, until the scenarios holding the `run: agent` cases of the areas it touches passed (any FAIL or BLOCKED stops it; the PR lists the cases added, changed, removed and run, with results); a release runs every `critical` case, agent and manual, and links the report. Reports go to `tests/reports/` (git-ignored). Never use real call data in cases, reports or issues, only made-up people and companies. The older `tests/NN-*.md` files are being rewritten into `tests/cases/`: a rewritten one is removed. Evidence: `tests/app_profile.md::Rules`
- R5. `scripts/check-mod.sh` is the list of mod and window checks (plugin validate and test, every `ui/*.test.mjs` it names, tsc); read the script rather than a copy of its list, and note its tsc step prints `skip tsc` and passes when no Claude Code type declarations are found. Evidence: `scripts/check-mod.sh::node`
- R6. On Windows before a release, run the native check of the code behind `tray` and `brain` that the macOS cross-check skips (the command is in quality-gates.md, Full runs). Evidence: `crates/echoctl/Cargo.toml::features`
